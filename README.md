# ReconMind — Agentic AI Security Platform

> **Attack · Observe · Verify · Learn**

ReconMind is an end-to-end security evaluation platform for LLM-based multi-agent systems. It is **not a chatbot** — it orchestrates adversarial attack campaigns against agentic AI pipelines, captures structured execution traces, verifies outcomes via oracle-based ground truth, and trains ML models for automated attack detection and classification.

---

## Architecture

```
User Input ──► Input Validation ──► Intake Agent ──► Retrieval Agent ──► Shared Memory
                                                                              │
                    ┌─────────────────────────────────────────────────────────┘
                    ▼
              Action Agent ──► Tool Layer (DB / API / Email)
                    │
                    ▼
           Structured Logging ──► Oracle Verification ──► Dataset Builder
                                                              │
                                                              ▼
                                                    ML Models ──► Analytics Dashboard
```

### Key Components

| Layer | Description |
|-------|-------------|
| **Multi-Agent Pipeline** | LangGraph-orchestrated agents (Intake → Retrieval → Action) with shared SQLite memory |
| **Attack Framework** | 4 attack types with configurable payloads and injection strategies |
| **Defense Layer** | Heuristic filters + LLM-as-judge defense mechanisms |
| **Oracle Verification** | Multi-signal ground-truth engine (judge check + memory check + tool check) |
| **Campaign Runner** | Automated attack matrix execution with structured trace export |
| **ML Pipeline** | BiLSTM with attention + multi-task classification heads |
| **Dashboard** | React-based analytics frontend (deployed on Vercel) |

---

## Attack Types

| Attack | Description |
|--------|-------------|
| **Direct Prompt Injection** | Adversarial prompts targeting the intake agent to override system instructions |
| **Indirect Prompt Injection** | Payloads embedded in retrieved context (tool outputs, memory entries) |
| **Memory Poisoning** | Corrupting the shared memory store to influence downstream agent behavior |
| **Tool Misuse** | Crafted inputs that cause agents to invoke tools in unintended or harmful ways |

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Agent Orchestration | LangGraph |
| LLM | Qwen 2.5 via Ollama (fully local, no API keys) |
| Memory | SQLite |
| Verification | Multi-signal Oracle Engine |
| ML Model | BiLSTM with self-attention, multi-task heads (binary + outcome + type) |
| Text Embeddings | all-MiniLM-L6-v2 (384-dim sentence embeddings) |
| Benchmark | AgentDojo (open benchmark for LLM agent security) |
| Backend | FastAPI |
| Frontend | React + Vite + Tailwind CSS |

## Dataset

Traces are generated by running attack campaigns through the agent pipeline and collecting per-hop structured events.

| Dataset | Runs | Events | Source |
|---------|------|--------|--------|
| AgentDojo Banking (validated) | 250 | 8,373 | AgentDojo banking environment |
| AgentDojo Full (all suites) | 1,087 | 27,063 | Banking + Workspace + Travel suites |

### Banking Suite Distribution
- **Clean runs:** 107 · **Attack runs:** 143
- **Injection types:** DoS (46), Indirect (29), Direct (21)
- **Outcomes:** Clean (107), Ignored (92), Partial (26), Full Success (25)

## Results

### Binary Attack Detection (is this trace an attack?)

| Model | Dataset | Binary F1 | AUC-ROC |
|-------|---------|-----------|---------|
| **BiLSTM + Attention** | Full traces (533) | 0.965 | 0.996 |
| BiLSTM + Attention | Full traces (535) | 0.953 | 0.996 |
| BiLSTM (Phase 2, 5-seed) | AgentDojo all suites (1,087) | 0.956 ± 0.003 | 0.601 ± 0.016 |
| BiLSTM | AgentDojo banking only (250) | 0.250 | 0.644 |

### Multi-Task Classification

| Model | Outcome Macro F1 | Type Macro F1 |
|-------|-----------------|---------------|
| **Deep Behavioral BiLSTM** | **0.943** | **0.612** |
| Deep BiLSTM (Track A) | 0.668 | 0.239 |
| AgentDojo-only BiLSTM | 0.149 | 0.509 |

> **Best model:** Deep Behavioral BiLSTM achieves **0.965 Binary F1** and **0.996 AUC-ROC** for attack detection, with **0.943 Outcome F1** for predicting injection outcomes. Type classification (distinguishing between attack categories) remains an open challenge at 0.612 Macro F1.

### Model Architecture
```
Input: [text_embeddings (384d), tabular_features (10d)] × 3 hops
  → Tab Encoder (Linear → ReLU → Dropout)
  → Concat [text + tab] per hop
  → Bidirectional LSTM (256 hidden, 2 layers)
  → Self-Attention pooling
  → Multi-task heads:
      ├── Binary (attack / clean)
      ├── Outcome (clean / ignored / partial / full_success)
      └── Type (direct / indirect / dos / memory_poisoning / tool_misuse)
```

## Getting Started

### Prerequisites
- Python 3.10+
- [Ollama](https://ollama.com/) with Qwen 2.5 model pulled
- NVIDIA GPU recommended for ML training (CUDA)
- Node.js 18+ (for frontend)

### 1. Setup Virtual Environment
```bash
python3 -m venv .venv
source .venv/bin/activate   # Linux/macOS
# .venv\Scripts\activate    # Windows
```

### 2. Install Dependencies
```bash
pip install -r requirements.txt
```

### 3. Start Ollama
```bash
ollama pull qwen2.5
ollama serve
```

### 4. Run an Attack Campaign
```bash
# Clean run (single campaign)
bash run_clean.sh

# Full AgentDojo benchmark
bash run_local_agentdojo.sh
```

### 5. Train ML Models
```bash
# Train on AgentDojo traces
python analytics/train_agentdojo.py

# Multi-seed evaluation
python train_phase2.py
```

### 6. Launch Dashboard
```bash
# Backend
python -m reconmind.api.server

# Frontend (separate terminal)
cd frontend && npm install && npm run dev
```

## Known Limitations

- **Type classification** is the weakest task — best Macro F1 is 0.612; the model struggles to distinguish between attack categories
- **Small dataset** — 250 validated banking traces is insufficient for robust generalization
- **Phase 2 AUC-ROC (0.601)** suggests potential class-imbalance exploitation on the expanded dataset
- **Local LLM** (Qwen 2.5 via Ollama) is slower than API-based models; campaign runs take significant time
